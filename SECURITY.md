# Security and responsible use

Use public information and targets/files you have permission to inspect. This project does not implement authentication bypass, private-account access, credential testing, password guessing, active port scanning or CAPTCHA evasion.

Report reproducible code vulnerabilities through the repository's private security reporting feature if enabled; otherwise open an issue without sensitive targets or secrets and request a private channel. No security contact address is invented here.

Before sharing an export, inspect metadata, local paths, public-source payloads and AI prose. Do not publish runtime data/secrets. HTTP protections apply to built-in adapters; third-party executables are separately maintained, not sandboxed. Keep dependencies updated following their advisories and re-run tests when changing versions.
