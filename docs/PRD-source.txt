 01 / Executive decisions
 OSINTCLI modernizes existing open-source OSINT capabilities into one usable, local-first terminal framework.
 The differentiator is not a collection of shortcuts; it is a unified investigation pipeline with verifiable
 provenance, deduplicated evidence, resilient jobs, optional AI narration, and production-quality reports.

  • V1 is a real terminal application, not a web dashboard. Users type a menu number and press Enter.
  • Android Termux is the acceptance platform; Linux VPS is the development environment, not a mandatory
    hosted service.
  • Investigative collection uses lawful public information and authorized targets. No authentication bypass,
    private-account access, credential testing, or intrusive scanning by default.
  • Clone and study upstream repositories; integrate selectively by adapter or legal reuse. Never imply that all
    repositories have identical licenses or Termux support.
  • SQLite requires no account or server setup. Installer/bootstrap creates its data directories and schema
    automatically.
  • AI does not perform OSINT collection, calculate statistics, infer identities without evidence, or compose
    charts. It rewrites and summarizes supplied evidence only.
  • Reports remain available when the AI endpoint is offline; failure must not prevent PDF generation.

 Normalized evidence schema
 Each piece of evidence must contain: id, case_id, entity_type, normalized_value, title, raw_value or file
 reference, source_url/source_name, adapter_id, collected_at (UTC), scope_id, status, verification_reason,
 confidence_basis, digest/hash, and error_code. Store raw and normalized evidence separately; preserve
 provenance.

 Evidence status: VERIFIED, CANDIDATE, UNVERIFIED, FAILED_SOURCE, STALE. Do not call an HTTP 200
 response or matching username a verified identity. Confidence must be rule-derived and explained, not
 guessed by the LLM.

 SQLite and file storage
 ~/.local/share/osintcli/osintcli.db       [Termux/Linux app data]
 ~/.local/share/osintcli/cases/<case-id>/
 ~/.local/share/osintcli/reports/<case-id>.pdf
 ~/.config/osintcli/config.toml           [nonsecret config]
 ~/.config/osintcli/secrets.toml          [mode 0600 if any]
 Create SQLite schema and apply versioned migrations on first launch/update. Enable foreign keys and WAL
 only where suitable, run backups before migrations, and do not store unencrypted credentials inside evidence
 or exports.


 06 / Mobile CLI design specification
 Primary viewport: 40 terminal columns (also test 32, 60, 80 and 120). Detect terminal size, ANSI color
 capability and Unicode support. Use narrow panels; automatic wrapping; short labels; menu numbers + Enter;
 non-interactive fallback. No browser and no physical keyboard required.

  Screen                     Required behavior


  Splash                     Small, recognizable icon ANSI art only; then OSINTCLI/version/by R_HMT and system status.


  Module menu                Single-column numbered menu; fit 40 columns; scroll/paginate where needed.


  Scan screen                Target, scope, source-stage, elapsed time, success/errors, cancel hint; honest statuses.


  Evidence list              Source+time+verification badge in compact multiline rows; inspect individual evidence.


  AI settings                Endpoint, HTTP method, optional headers, URL parameter, parser path, timeouts, editable custom
                             instructions.


  Reports                    Choose summary/full, include AI yes/no, export directory, preview and error diagnostics.

 08 / Nexray AI endpoint: replace Gemini
 Preset endpoint: https://api.nexray.eu.cc/ai/claude with GET query parameter text. Example supplied by
 project owner:

 curl -X GET "https://api.nexray.eu.cc/ai/claude?text=Hai"
 Observed in a public web retrieval on 17 Oct 2026: JSON containing status=true and result="Hai! How can I
 assist you today?". This demonstrates a basic response only. A second direct network test from the document
 runtime was blocked by DNS resolution; it cannot certify long-context, availability, security or report quality.

 Provider-neutral adapter / configuration
 provider = "nexray_http"
 endpoint = "https://api.nexray.eu.cc/ai/claude"
 method = "GET"
 input_parameter = "text"
 response_text_path = "result"
 success_path = "status"
 timeout_seconds = 25
 max_url_length = 1800   # safety cap; tune after testing
 The adapter must percent-encode the text query, validate TLS, restrict redirects, set timeout, inspect HTTP
 status/content type, validate expected JSON schema, enforce response length limits and reject HTML/empty
 replies. Never invent an API key requirement; only show optional header/auth settings if provider needs them.
 Endpoint may change or disappear.

 Important: GET carries prompt text in URL/query logs and may hit URL-length limitations. The app must warn
 before sending evidence externally, redact or minimize sensitive fields, cap GET payload and refuse
 unsafe/oversized uploads. If the endpoint has no documented POST support, do not claim POST works;
 support a second provider profile with POST only after testing it.

 Editable custom instruction template
 Recommended default: “Anda adalah editor laporan OSINT. Gunakan hanya fakta pada EVIDENCE_JSON.
 Jangan menambah alamat, identitas, angka, sumber, waktu atau kesimpulan yang tidak ada. Pisahkan
 temuan terverifikasi, kandidat, dan keterbatasan. Tulis Bahasa Indonesia yang jelas, teknis, ringkas, dan
 netral. Jangan mengklaim bahwa dua profil milik orang yang sama hanya berdasarkan username. Jika bukti
 tidak cukup, katakan tidak cukup.”

 Allow a separate user custom instruction saved locally, versioned per report. Treat source data as untrusted
 and surround it with clear structure; ignore any instructions embedded in gathered pages. Show the
 combined prompt and evidence subset before sending.

 LLM output contract
 Preferred fields: summary, key_findings, limitations, conclusion; optionally confidence_explanations. Validate
 with a typed parser. If provider only returns freeform text, perform strict sanitization, map sections
 defensively and require user review. Do not let LLM set numeric totals, overwrite evidence or add unsourced
 charts.

 AI reliability tests
  • GET smoke request and schema parsing; malformed JSON, empty result, status=false, non-200 and HTML
    response.
  • URL encoding for spaces, Bahasa Indonesia punctuation, Unicode and special characters.
  • Input overflow and URL-too-long failure: no silent truncation; local report still generated.
  • Timeout, DNS failure, TLS failure, rate limits, retry/backoff and circuit breaker; no infinite loops.
  • Prompt-injection fixture: source data contains “ignore previous instructions”; AI summary must not follow
    it.

 09 / PDF reporting contract
 The PDF engine is deterministic and local. Use ReportLab + locally generated graphs (Matplotlib) and carefully
 tested fonts. Tables are produced from normalized evidence, never fabricated by AI. Record report ID, case
 ID, generation timestamp, generator version, dataset digest, AI provider (if any) and verified source
 references.

 Required report outline
  • Cover: OSINTCLI visual identity, target, case ID, report date and confidentiality note.
  • Executive summary: case metadata, source coverage, accurate counts; optional reviewed AI narration.
  • Methodology: permitted scope, selected modules, collection windows, retrieval limits and known gaps.
  • Evidence overview: counts by category/status, module success/failure, collection timeline.
  • Evidence tables: normalized values, verification reason, URL/source, date/time and uncertainty.
  • Data charts: bar chart by category, status distribution, time series only when dates support it.
  • Relationship diagram: only source-backed entity links; show legend and edge evidence.
  • Analysis & conclusions: separate observations from hypotheses; clear confidence basis.
  • Appendix: sources, errors, missing sources, module versions, hash/trace, full evidence references.

 Export capabilities

  Type                Rules


  PDF                 A4 portrait, page breaks, embedded fonts, wrap long URLs, repeat table headings, clickable source links.


  JSON                Canonical machine-readable evidence and report metadata with version field.


  CSV                 Flattened evidence table with safe escaping for formula-injection characters.


  HTML                Optional accessible standalone report; sanitize untrusted input.


  Images              PNG charts exported with explicit source data and generated timestamp.




 PDF acceptance criteria
  • At least one fixture with 0 records, one with 100+ records, Unicode names, Arabic/Indonesian text and very
    long URLs.
  • PDF can open on Android PDF viewers and desktop; no broken glyphs, clipped tables, blank charts, overlap
    or missing sources.
  • Compare graph sums to evidence queries. Inject mismatched AI counts and prove they cannot alter
    computed statistics.
  • No-AI report completes even if Nexray returns an error or goes offline.
  • Metadata-only investigation still produces a coherent report without invented domain/IP results.
  • Report filename is sanitized; save atomically and recover safely from interrupted export.
  • Add golden/PDF render snapshot tests and inspect page images, not only file existence.

 13 / Security, quality and release governance
  • Default collection is passive and permission-aware. Do not ship exploits, phishing, brute force, secret
    extraction or stealth features.
  • Reject local/internal address redirection for remotely retrieved arbitrary URLs; for user-authorized local
    files, use safe path handling and size limits.
  • Use least privilege and do not require root or extra Android permissions except when functionally
    necessary.
  • Mask sensitive content and API keys in tracebacks; set file permissions; support “delete case” and
    controlled export.
  • If package is bundled with GPL/AGPL components, verify obligations in writing. Attribution alone may be
    insufficient.
  • Automated tools should never claim verified identity from a name collision; always show source and
    confidence basis.
  • When external AI is enabled, consent is per submission of evidence set; avoid sending sensitive evidence
    by default.
  • Document known paid API sources as optional, not misleadingly label every source free.
